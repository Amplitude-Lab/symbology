# Symbology repository audit — 2026-09-09

Audit against the four design principles: **robustness** (no silent failures,
safe on huge data), **efficiency** (solver-class code as fast as exactness
allows), **universality** (blocks general beyond their originating physics),
**transplantability** (design on the laptop, run the compiled calculation
anywhere the C++ core builds).

Method: full read of the calculation core and front-end; every fix gated on a
bit-identical CRC32 baseline (`make regression`, two manifests:
`baseline-2026-09-09/manifest.json` = the 19-step `NMHVw2collinear` flow,
`manifest-singlepair.json` = single-pair `SEW_3p1` solve); differential
old-vs-new binary builds for the riskiest rewrites; engine-level and
exported-script end-to-end runs.

Severity: **P0** silent wrong result / data loss · **P1** robustness (loud
failure missing, races, unbounded resources) · **P2** efficiency ·
**P3** polish/docs.

### Known limitations (documented, not fixed this pass)

- **P2**: `bootstrap --solve-collinear` exits 0 on a loudly-reported
  *inconsistent* system (no solution written). With R3/R4 the run now fails
  at that step, which is the right flow-level semantics, but the C++ exit
  code itself remains 0. Recommendation: exit nonzero on inconsistency
  (would change scripted consumers; kept for compatibility this pass).
- **P2**: the server is localhost-only with no auth by design (documented);
  `import_alphabet` will copy any absolute path the request names. Acceptable
  for a single-user local tool; do not expose the port.
- **P3**: front-end SSR audit (`web/scripts/ssr-audit.sh`) fails on the
  currently installed esbuild: relative alias names (`../api`, `../App`) are
  rejected. Predates this audit. Fix by stubbing through a package-style
  alias or a build plugin; `vite build` is unaffected.

All changes gated on bit-identical outputs (`make regression`) — required and
achieved for every item below.

| # | Finding | Evidence | Change | Result |

| E4 | Benchmark coverage was ad hoc. | — | `make bench` (`bench/crc_bench.cpp`); regression manifests double as performance smoke (deterministic step timings in logs). | Reproducible numbers on any machine. |

### Deferred with rationale (follow-up candidates)

- **`build_condition_matrix`** per-row `std::map` accumulation
  (`tensor_ops.cpp:205-237`): exercised only via `icond/impose` flows that
  the baselines don't cover; blind optimization without coverage contradicts
  the audit's own discipline. Add an `icond` manifest first.
- **Fallback-path copies in the solvers** (`linear_solve.hpp` `M_sub`/`full_aug`
  duplication; `incremental_solve.hpp:444-458` copy): fire only on
  verification-failure/underdetermined fallbacks — low frequency by design.
- **`compute_rhs` write-then-immediately-reread** (`compute_rhs.hpp:614-637`):
  the C++ `compute_rhs` binary is not exercised by any flow (the flow editor
  implements the correct recursion as `tensor_ops` steps); optimize only after
  a baseline manifest covers it, or retire the divergent C++ path (see U2).
- **Threading**: incremental-elimination is single-threaded (the fallback
  multimodular RREF is threaded). A parallel `reduce_fully_against_basis`
  is the highest-value follow-up for cluster runs; requires its own
  differential harness.
- **Whole-file-in-RAM** is the pervasive I/O model (now documented in the
  script preflight as a RAM consideration); mmap revival would need a real
  design, not the removed dead code.

## 4. Transplantability

**Key structural finding**: the front-end compiled flows to an internal JSON
step list executed only by the local server — there was **no standalone
"compiled CLI script" artifact** to copy to a supercomputer, despite the
design intent. The export below closes that gap.

### New: standalone script export (P0 for the principle)

`export_flow_script` (`compile.py`) + `POST /api/projects/{pid}/flows/{fid}/export_script`
+ "⇪ Export standalone script" button in the CompilePanel. Produces
`projects/<pid>/exported/<flow>.sh` — same compiled steps as the engine runs,
rendered as a portable, self-checking bash script:

- `set -euo pipefail`; loud `fail()` with step context, log tail, disk state.
- **Preflight**: binaries executable, seed inputs present with sizes, free
  disk on the output dir, wolframscript probe.
- **No-Mathematica mode** (the chosen cluster profile): Wolfram steps are
  skipped with loud warnings when their outputs already exist (copy from the
  laptop), else fail — `WOLFRAM_MODE=skip` forces skipping.
- Per-step banners, wall timings, full output tee'd to
  `runs/exported-<timestamp>.log`, optional `STEP_TIMEOUT`.
- **Post-step verification** (mirrors R3) + CRC32 echo per output.
- **Resume**: fingerprint cache (command + input size/mtime) writes
  `.sig.exported` sidecars — deliberately independent from the server's
  `.sig` (a mismatch costs a recompute, never a stale skip).
- Paths relativized to `$SYMBOLOGY_ROOT` / `$PROJ_DIR` / `$WOLFRAMSCRIPT`;
  `--dry-run`, `STEPS="3,5-9"` subset selection; bash-3.2-safe.
- Verified: relocated-sandbox fresh run + resume reproduce the audited
  baseline CRC exactly.

### Fixed

| # | Finding | Fix |
|---|---------|-----|
| T1 | `-mcpu=native` is ARM-speak; x86_64 GCC wants `-march=native` for ISA dispatch (HPC boxes are x86_64). | Per-arch `ARCH_FLAGS` in the Makefile. |
| T2 | `-lmimalloc` hard-required — commonly absent on HPC. | Probed (Homebrew / usr/local / Debian multiarch), overridable `MIMALLOC=0/1`; math identical without it. |
| T3 | A machine-specific `tensor_ops` Mach-O binary was **committed to git** (and tracked as modified forever). | Untracked (`git rm --cached`; working file kept) + `.gitignore` now lists `tensor_ops`/`tensor_add` (staged for the next commit). |
| T4 | `run_workflow.sh` hardcoded `/opt/homebrew/bin/g++-14`. | Plain `make` (the Makefile's Homebrew detection is the single source). |
| T5 | SparseRREF setup was manual clone+checkout+apply with no verification script. | `scripts/setup-sparserref.sh` (clone pinned `5bbee55`, apply patch, `--check` verifies the two atomic occurrences + loud-failure markers); verified against a fresh upstream clone. |
| T6 | Generated Wolfram scripts baked absolute package/output paths. | `Get[SymbolBootstrap.wl]` resolves through `$SYMBOLOGY_ROOT` (env override, baked default) — `GetEnvironment` return-shape pitfalls tested in both states. |

### Cluster prerequisites (documented in README)

GCC ≥ 12 (libstdc++), FLINT, GMP, TBB, python3 (fingerprints/CRC echoes);
mimalloc optional; Mathematica not needed for solve pipelines (only for
alphabet property recomputation, which can instead be copied via the project
dir).

## 6. Recommended follow-ups — **all completed 2026-09-10**

1. **Baseline manifests for `icond` + `compute_rhs`** — DONE.
   `manifest-icond.json` (icond×2 + join + isolve chain lifted from recorded
   flow commands) and `manifest-computerhs.json` (compute_rhs at SEW_3p1 and
   SEW_5p1, recursive). `make regression` now gates **four** baselines.
2. **Nonzero exit for inconsistent solves** — DONE. Both solvers print the
   full union-matching diagnostics, then throw (rc=1) with the b-only count;
   negative-tested on the known-inconsistent identity projection at L=2
   (24 b-only, matching the skills/04 record).
3. **Deferred efficiency items under that coverage** — DONE.
   `build_condition_matrix` per-row maps → flat append + sort + merge
   (bit-identical via the icond baseline); `compute_rhs` write-then-reread →
   in-memory handoff for hepMHV/E_L/boundary/R_L (bit-identical via the
   compute_rhs baseline). The solver fallback-copy item remains deferred
   (fallback paths only, low frequency).
4. **C++ `compute_boundary` recursion port (U2)** — DONE. The hardcoded
   L=2..5 closed forms (incl. the known-wrong L=5) are replaced by the
   master-equation recursion `boundary_L = (1/L)·Σ k·(R_k ⊗ E_{L-k})`,
   `R_1 := E1`. **Bit-identical to the closed forms at L=2 and L=3**
   (`boundary_3L dc117613`, `E3 b081a89d`, `hepMHV_3L 312a3106`, solutions
   `c={8}`, `{−24,2}`) — this also re-verifies the previously
   "pre-fix pending" skills/README L=3 row. The L≤5 cap now comes solely
   from the shuffle kernel's weight-11 limit.
5. **Parallel incremental-elimination** — DONE. Batch rows are pre-reduced
   against the frozen basis in parallel (`kParallelRows = 64` threshold),
   then inserted sequentially with re-reduction — over exact rationals the
   confluence of reduction makes the basis evolution, diagnostics and
   solution **identical** to the sequential interleaving. The substitution
   and final-verification sweeps are parallelized the same way
   (flag-in-parallel, filter-in-order). Verified: 4 baselines bit-identical
   + the 56-case Wolfram-ground-truth fuzz suite (all verdicts, solutions,
   null spaces; the n=30/R=700 cases exercise both parallel paths).
6. **`ssr-audit.sh` esbuild aliasing** — DONE. Stub routing moved to an
   `onResolve` plugin (`scripts/ssr-audit-build.mjs`) since relative alias
   names are not CLI-expressible; `.mjs` JSX loader set. Audit green:
   1072 renders OK, 0 problems.
7. **`make check` + CI** — DONE. `make check` = regression + registry sync
   (green locally). `.github/workflows/check.yml` runs the
   machine-independent subset on GitHub (C++ build against a fresh
   SparseRREF clone + patch, sync check, web bundle build); the CRC32
   baselines stay local (`front-end/projects/` is gitignored).
   **Caveat**: the workflow is untestable from this machine — the FLINT ≥ 3
   requirement against Ubuntu's `libflint-dev` may need a version pin on
   first run.
