# Keeping heptagon recursion sparse

The optimized factorized backend brings the tested heptagon runs into the
same order of runtime as the original solver. It preserves an exact,
irreducible representation of the answer at every weight, while retaining a
sparse internal carrier for the following solve.

This is an architectural tradeoff: the new backend uses full sparse Gaussian
elimination internally. It does **not** establish that multiplicity-only
elimination is as fast as the ordinary solver. The existing reduced-unknown
backend remains available as `--backend multiplicity`; the new backend is
`--backend factorized`. `auto` chooses factorized for non-split rational
irreps, including this heptagon, and keeps the multiplicity backend for the
split hexagon models. This heuristic is overridable.

Each entry is the median of three sequential fresh processes with two workers,
the same GCC 14.4 / FLINT 3.2.2 toolchain, and the repository's patched

Times include process startup, solving, maintaining the chosen output
representation, WXF export with readback, and bundle sealing. The ordinary
solver stores a sparse basis without an irreducible frame; the factorized
solver additionally stores that frame, its copy layout and generator actions.
OS file caches were not flushed. Input preparation is reusable and measured

One-time preparation took 0.338 s for heptagon FEC and 0.332 s for LEC.

export, rather than the 0.21 s factorized timing. Expanded export at the

## Why the earlier reduction was slower

The multiplicity algorithm correctly reduced unknowns and equations together.
It was not simply sorting an ordinary kernel afterward. The problem was the
coordinate system and its growth under recursion.

At heptagon LEC weight 3, the original equations have 4,956 columns and 102,551
nonzero entries. The reduced QQ corner systems use only 2,832 columns across
six blocks, but have 1,364,502 nonzero entries. A smaller number of unknowns
therefore came with over thirteen times as many nonzero coefficients, together
with large rational coefficients and expensive lattice shortening. The
preceding expanded canonical output had 747,853 nonzeros. Feeding such
coordinates into the next contraction perpetuates the problem.

The selected heptagon group is D7 × C2, generated by cyclic, flip and parity.
Its rational irreps have dimensions `1,1,1,1,6,6`. The two six-dimensional
irreps have three-dimensional endomorphism fields. The rational corner
reduction halves the number of component unknowns in those sectors; it does
not give a sixfold reduction over QQ. Fewer columns alone could not offset
fill-in and coefficient growth.

Exploratory changes to field reconstruction, projector coordinates, lattice
batch sizes and generator selection improved some phases but did not remove
this recursive density cost. In particular, removing lattice shortening
without changing the basis representation made later rational operations
worse. These exploratory implementations were not retained in the production
headers. Their source snapshots and logs remain in the ignored local output
folder for inspection.

## The optimized recurrence

Let `C_w` be the sparse working basis and `H_w` its square irreducible frame.
The logical answer is `B_w = H_w C_w`, with rows ordered by irrep, copy, and
component. Let `S_w(g)` act on the carrier and `D_w(g)` be the canonical direct
sum of rational irrep models. The frame obeys

```text
H_w S_w(g) = D_w(g) H_w.
```

1. Assemble the new equations using the preceding sparse carrier and the
   original independent condition rows. Solve with the existing QQ SparseRREF
   kernel routine, and retain native primitive normalization and row ordering.
2. Recover the group action on that kernel through its free-coordinate chart.
   Construct only the tensor-action columns needed by the chart, instead of
   multiplying by a full ambient action matrix.
3. Over a good finite field, form the primitive projectors of this much smaller
   kernel representation. Restrict rank selection to independent columns of
   each primitive corner. Select enough cyclic generators to cover every copy.
4. Evaluate only those selected projector rows over QQ. Batch the required
   unit-vector orbits through SparseRREF's worker pool. Generate all remaining
   components of each irreducible copy by the model's fixed group words.
   Normalize all rows in a copy by one common scalar.
5. Store the sparse recurrence, frame, generator actions and copy boundaries.
   The next weight consumes the sparse carrier and its inherited actions;
   expanding the frame into the recursive tensor is unnecessary.

This keeps the logical input and output irreducibly organized, although the
internal elimination coordinates are sparse carriers. The prepared data still
contain the symmetry-adapted condition and its reduced endomorphism
coefficients, which the multiplicity backend uses. The factorized backend uses
the original independent condition rows with the same certified symmetry.

At LEC weight 3 the carrier contains 43,712 nonzeros and its frame contains
43,614. Thus the factorization avoids materializing the large canonical tensor
in the recursive solve. It also avoids constructing all group action matrices
over QQ; only generator matrices and selected row orbits are needed.

## Exactness and verification

Finite-field arithmetic is used for selecting independent frame generators,
not approximating the rational answer. A nonzero modular minor proves QQ
independence. An idempotent's trace is its rank, an integer between zero and the
kernel dimension. At a prime larger than that dimension with invertible
coefficient denominators, the modular trace identifies the exact rank.
Covering every primitive corner and the full kernel dimension therefore
certifies completeness. Bad denominator primes are retried.

The model construction proves the orbit identities inside the rational group
algebra. Evaluating these identities in any representation gives the frame
intertwiner identity. The kernel inherits a representation because the
prepared constraints are equivariant and the solve is exact. The fast driver
uses this universal proof; `--compare` additionally checks the full ambient
carrier intertwiners, rational kernel residual, frame intertwiners and frame
invertibility directly. This removes redundant large verification products
from the timed path without replacing exact algebra with a tolerance.

Every benchmark repetition is independently compared to the native chain at
every weight. Verification constructs an invertible exact rational change of
basis recursively, substituting the carrier-to-reference change at the next
weight and writing the irreducible-to-reference change for inspection. It
also checks saved frame invertibility and intertwiners. The hexagon chains are
additionally checked against the actual unpacked package. Expanded heptagon
exports are separately verified against the native chain.

The additional full-matrix comparison runs passed for heptagon FEC through
weight 5 and LEC through weight 4. These optional diagnostic runs took 0.98 s
and 18.24 s respectively; they are excluded from the fast-path timings. Logs
are saved alongside this report.

Public checks pass for nine finite groups, including C3, D3, D7 and Q8, with
rationally conjugated representations, non-scalar commutants, independent
full ambient-action comparisons, and a denominator-prime retry fixture. CLI
checks cover both recurrence directions, saved continuation, vector terminals,
zero and unconstrained spaces, factorized export and continuation of exported
chains, incorrect backend/format combinations, and bundle integrity. A public
C3 fixture also verifies automatic nonsplit backend selection and continuation
from a weight-one-only chain. The original native calculation core is unchanged.

## File format, continuation and compatibility

A factorized chain has version `symbology-symrep-chain-v2` and contains:

- `wN_carrier.wxf`: sparse recurrence in original letters and previous carrier
  coordinates.
- `wN_frame.wxf`: the exact square map to irreducible rows.
- `wN_carrier_gJ.wxf`: carrier action of defining generator `J`.
- `wN_copies.tsv`: logical irrep, copy and component boundaries.
- `chain.tsv`, `checksums.tsv`: convention binding, format and complete-file
  integrity checks.
- `timings.tsv`: assembly, kernel, action, frame and optional verification
  times, plus matrix sizes and nonzero counts.

`extend --chain` resumes either format and follows it under `--backend auto`.
The expanded v1 format remains available through `symrep expand`; it can also
be continued by the multiplicity backend. For FEC its recurrence is

```text
H_w C_w (H_(w-1)^(-1) tensor alphabet_basis^(-1)).
```

For LEC reverse the two tensor factors on the right. Weight one uses the
prepared terminal basis in place of `H_0`. Export time is not hidden inside the
factorized timings. No native solver or SparseRREF calculation core was
changed.

The new representation and command usage are documented in
[`../../docs/symrep.md`](../../docs/symrep.md). The reproducible benchmark is
[`../../bench/symrep_carrier.py`](../../bench/symrep_carrier.py). Full local
outputs, logs and the timed source snapshot are under
`output_symrep_sparse_20261002/validated/`; compact measurements and source
hashes are saved in this audit directory. No generated benchmark tensors
or compiled binaries are part of the source changes.

## Remaining limits

Maintaining an irreducible frame costs additional time and memory, and that
cost grows with the kernel. This is not a guarantee that every finite group,
coordinate system or future weight will run within a fixed factor of native.
Expanded output can be substantially more expensive than the factored form.
The next optimization target for larger weights is modular projector and
frame construction; the previous dense multiplicity contractions are no
longer on this backend's recursive path.

Reproduce the timing audit (after building the solver, native helper and archive
exporter with the recorded flags):

```bash
python3 bench/symrep_carrier.py \
  --before output_symrep_sparse_20261002/before/symrep \
  --native output_symrep_optimization_20261002/native_reference \
  --archive /home/ana/Downloads/hexagon_irr_bootstrap_v2_20260928_inspected/hexagon_irr_bootstrap \
  --references output_symrep_validated_20261001 \
  --output output_symrep_carrier_reproduction --repeats 3
```

[`results.json`](results.json) contains all process measurements and per-weight
phase timings. [`source-manifest.json`](source-manifest.json) records the
compiler, build flags, prepared-bundle hashes, preserved baseline executables,
and timed/current source hashes. The solver sources and binary are identical
to the timed snapshot; later changes only strengthen test/audit orchestration
and document the results.
