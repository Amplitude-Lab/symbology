# Four-loop four-point MHV form-factor benchmark

## Accepted result

This benchmark reconstructs the weight-eight (four-loop) four-point MHV
form-factor symbol in the finite normalization on the retained 88-letter
alphabet. The accepted tensor is
[reference/F4_candidate_prefix6_suffix2.wxf](reference/F4_candidate_prefix6_suffix2.wxf):

- shape `1 × 35598 × 175`;
- 988,559 nonzero coefficients;
- 22,457,737 bytes;
- SHA256 `5fd5b1d60c703bd303804307d467aec7b713213e278c923707db6580e0238f38`.

It is byte-identical to the DC and TC affine-solve origins. Both reserved
finite-descendant holdouts pass exactly. The result is unique within the
explicit proposed-adjacency and continued twelve-dimensional literature
remainder (TR12) hypotheses. External Steinmann equations were not imposed;
finite four-loop targets did not enter the solve. No all-loop, larger-ES
uniqueness, full-parent, or function-level claim is made.

## How to replay

Run all commands from the repository root. Output directories must be fresh.

### 1. Verify the package (seconds)

```bash
python3 bench/four_loop_formfactor.py verify
```

This checks every manifest file, certificate chain, boundary block chain,
Lucas prime certificate, holdout receipt and guard hash.

### 2. Regenerate the accepted core and final result

```bash
python3 bench/four_loop_formfactor.py run-core \
  --output output/formfactor-4l-core

python3 bench/four_loop_formfactor.py replay-final \
  --sewing-dir output/formfactor-4l-core \
  --output output/formfactor-4l-core-final
```

The only accepted sequence is:

1. FEC_3→FEC_6 with `bootstrap --extend`, starting from committed FEC_2;
2. LEC_2→LEC_4;
3. `galois`, `galois_suffix`, `actions_structural` prefix actions, and `actions`
   suffix actions through weight 2;
4. `sew_affine_TR_build_v1` affine-TR sewing;
5. `affine_TR_extract` in `tr` mode;
6. DC then TC exact affine boundary solves and both reserved holdouts.

The runner uses an explicit accepted-stage allowlist. It never selects stages
by scanning and executing arbitrary historical receipts. Every regenerable
accepted output is compared byte-for-byte: FEC_3/4/5, LEC_2, the affine-TR
matrix, affine origin and TR92 directions. DC and TC must both reproduce the
accepted candidate hash. New core runs write `core_stage_receipts.jsonl` with
commands, wall times and sampled peak RSS.

### 3. Replay only the final stages (about 2 minutes)

To use the committed sewing outputs rather than a fresh core result:

```bash
python3 bench/four_loop_formfactor.py replay-final \
  --output output/formfactor-4l-replay
```

Solver binaries are resolved from `--solver-bin DIR`, from receipt-checked
local binaries, or compiled from `solver-source/`. Every final stage runs
under the 12 GB sampled memory cap and writes receipts.

## Inputs and outputs

| Object | Replay policy |
| --- | --- |
| Small seeds, symmetry matrices, TR constraints and affine sources | Committed and hash-bound in `manifest.json` |
| FEC_2, candidate tensor, LEC_2 and suffix decoding bases | Committed and hash-verified |
| FEC_3…FEC_6, including 503 MB FEC_6 | Regenerated by `run-core` |
| Symmetry actions | Regenerated by the accepted helpers |
| Affine-TR matrix, origin and TR92 directions | Regenerated and byte-compared; committed copies retained |
| DC/TC weight-6 projection maps | Committed xz-compressed inputs, decompressed by the runner |
| Reserved holdout targets and certificates | Committed and used only after the candidate is fixed |
| Solver binaries | Compiled from committed sources or checked against receipt-pinned hashes |

This replays the accepted packaged pipeline. It does not re-derive the
committed boundary-preparation maps or earlier research-stage constraints.
